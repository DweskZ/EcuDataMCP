The backstage

Open-source MCP server.

EcuDataMCP runs as a Python server built with the official MCP SDK, exposed over Streamable HTTP or stdio. There is no database of its own: every tool calls the matching official portal live (CKAN, gob.ec, SERCOP, BCE, Supercías, IG-EPN, SGR) and returns the formatted response.

Frequently asked questions

Got more questions?

What is EcuDataMCP?

An open-source MCP (Model Context Protocol) server that helps your AI assistant discover and query Ecuador's open government data: datasets, procedures, regulations, public contracts, risk events, earthquakes, Central Bank indicators, and companies.

What is MCP?

Model Context Protocol is an open standard for connecting AI assistants to external tools and data sources, while keeping control over what the model can do and what data it can read.

Is the data official?

Yes. Every answer comes live from the institution's own portal (BCE, INEC, SRI, Supercías, SERCOP…) and carries the link to verify it.

What assistants can I use?

Any MCP-compatible client: Claude Desktop, Claude Code, Codex, ChatGPT (paid plans), Cursor, VS Code, Gemini CLI, Le Chat, Windsurf, HuggingChat, and more.

Do I need an API key?

No. Every source the server uses is public data with no authentication. (The HTTP endpoint can be protected with your own token, MCP_AUTH_TOKEN.)

Is this an official service of the Ecuadorian government?

No. EcuDataMCP is an independent, open-source project that queries the same public sources the Ecuadorian state already publishes. It is not affiliated with any institution.

Does the server store my questions?

There is no external telemetry. The server runs locally on your machine, and every query goes straight from the MCP client to the matching official portal. The only thing recorded is local per-tool usage counters (name, outcome and duration, never the arguments).

What formats does it support?

In-memory preview of CSV, TSV, JSON, GeoJSON, and XLSX; filtered tabular queries via the CKAN DataStore when the resource supports it.

Something isn't working, where do I look?

Start with curl http://localhost:8000/health. If it responds, the problem is usually in the client configuration or the upstream portal. See the Troubleshooting section below.

Can I contribute?

Yes, the project is MIT-licensed and accepts pull requests. See the guide at Contribute.

Troubleshooting

Something not working?

Start by confirming the server is alive. If it responds, the problem is almost always in the client configuration or the upstream portal, not in EcuDataMCP.

curl http://localhost:8000/health

It should return {"status":"ok", "version": ...}. If it doesn't respond, the server isn't running or is listening on a different port.

My client shows no tools

Check, in order: (1) the server is running (/health responds); (2) the URL ends in /mcp, not / or /health; (3) the config JSON is valid (one stray comma silently breaks it); and (4) you fully restarted the client after editing the config. Claude Desktop, Cursor, and Windsurf only read the file at startup.

Claude Desktop or Windsurf: npx not found

The mcp-remote alternative (and the Windsurf config) needs Node.js 18+ installed and on the PATH. Install it from nodejs.org and restart the client. Node-free alternative: use stdio mode with uvx ecuador-mcp --transport stdio, or with "command": "uv" and "args": ["run", "--directory", "<clone-path>", "python", "main.py", "--transport", "stdio"].

Port 8000 is already in use

Start the server on another port (uv run main.py --port 8007, or MCP_PORT=8007 docker compose up -d) and change the client URL to http://localhost:8007/mcp.

In stdio mode the server exits immediately

Run the same command by hand in a terminal to see the real error. Typical causes are a wrong --directory path, not having run uv sync in the clone, or uv not being on the PATH the client sees (in that case, use the absolute path to uv).

ChatGPT or Le Chat can't reach localhost

Web clients run in the cloud and can't see your machine. You need to expose the server at a public HTTPS URL (a tunnel or your own deployment) and, in that case, enable MCP_REQUIRE_AUTH=1 with an MCP_AUTH_TOKEN. Never expose the server without a token.

401, 429, or 503 error from the server

401: the server requires a token (MCP_AUTH_TOKEN) and the client isn't sending it as Authorization: Bearer .... 429: you exceeded the per-window request limit (MCP_RATE_LIMIT_REQUESTS, 120 per 60 s by default); wait, or raise it for local use. 503: too many concurrent requests (MCP_MAX_CONCURRENT_REQUESTS, 8 by default).

403 error or timeout from the Open Data portal

www.datosabiertos.gob.ec sometimes rejects connections coming from outside Latin America (403 error). If you see this, run the server from a connection with an exit point in Ecuador or the region (a VPN, for example). The procedures and institutions tools use a different portal and don't have this issue. Government portals also have their own outages: if a single tool fails while the rest respond, try again later.

TLS / SSL certificate error

Some official portals have served expired certificates or incomplete chains (the Open Data portal's expired in July 2026). For that portal there's an opt-in retry: CKAN_INSECURE_TLS=1 in your .env. Use it only while the portal is broken and remove it afterward.

The preview is cut off or says the file is too large

That's intentional: downloads are capped at 5 MB and ZIP/tar.gz decompression at 20 MB. For large resources use query_resource_data (filters in the CKAN DataStore without downloading the file) or list_zip_contents to see what a ZIP contains and read_zip_member to read one of its files without downloading the whole ZIP.

I need more detail to report a bug

Start with LOG_LEVEL=DEBUG, reproduce the error, and open a GitHub issue with the tool, its parameters, the /health output, and the log. Don't include tokens.
