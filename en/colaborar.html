Contribute

Add your source, your tool, your idea.

EcuDataMCP is MIT-licensed and accepts pull requests. You don't need to be an expert in MCP or the whole project stack: most contributions touch a single piece.

Before you start

Check what's already in motion.

The ROADMAP.md tracks loose ends, candidate sources, and known issues: it's the best place to check whether your idea is already noted before opening a new issue.

Contribution flow

Fork, branch, PR.

01

Fork

Fork DweskZ/EcuDataMCP to your account.

02

Branch

git checkout -b feature/new-tool

03

Commit

git commit -m 'feat: add new tool'

04

Pull Request

Push to your fork and open a PR describing the change.

MCP server

Python, uv, pytest.

The server lives in tools/, helpers/, resources/, and prompts/. It requires Python 3.11+ and uv.

uv sync
uv run pytest
uv run ruff check .

A new tool is usually three files: the function in tools/, its registration in tools/__init__.py, and a test in tests/.

This site

All Python, no R or Quarto.

The site lives in web/ and uses Jinja2 (Python) to generate HTML from web/data/*.json. The source, tool, and MCP client cards are generated from those files: editing them is just JSON. No R or Quarto needed at all — the site builds with uv run python build.py like any other Python script in the repo. The full detail is in web/README.md, inside the repository.

Every missing source, every tool short on coverage, is a possible contribution.
