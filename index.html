Cómo funciona

Una pregunta, un camino trazable.

Tu asistente elige la tool adecuada, consulta en vivo el portal oficial y te devuelve el dato con su cita. Nada se copia ni se inventa.

Aviso: Algunas definiciones, parámetros y descripciones de herramientas fueron generados o asistidos por IA. Pueden estar incompletos o desactualizados; una herramienta puede devolver resultados parciales, rechazar parámetros válidos o comportarse inesperadamente cuando cambia la fuente oficial. Verifica siempre la respuesta contra la fuente enlazada y revisa manualmente los resultados antes de usarlos para decisiones importantes.

El backstage

Servidor MCP de código abierto.

EcuDataMCP corre como un servidor en Python construido con el SDK oficial de MCP, expuesto sobre HTTP Streamable o stdio. No hay base de datos propia: cada tool llama en vivo al portal oficial correspondiente (CKAN, gob.ec, SERCOP, BCE, Supercías, IG-EPN, SGR) y devuelve la respuesta formateada.

“¿Qué necesito para sacar el pasaporte por primera vez?”

Si eres mayor de 18 años: comprobante de pago (en línea, banco corresponsal o en la agencia) y cédula física o digital vigente; si renuevas, el pasaporte anterior. En Quito, Guayaquil y Cuenca lo entregan el mismo día; en otras agencias, en 24 a 72 horas.

Conecta tu asistente

Listo en un minuto.

Funciona con cualquier cliente MCP. Elige el tuyo y copia la configuración.

  • ✓Solo lectura: nunca modifica datos públicos
  • ✓Sin claves ni registro
  • ✓Código abierto con licencia MIT
  • ✓Disponible por PyPI, Docker o HTTP
Opción rápida: deja que tu asistente lo instale

Si tu asistente tiene acceso a una terminal, pégale el link del repositorio:

Clona https://github.com/DweskZ/EcuDataMCP, instala sus dependencias con uv sync,
y regístralo como servidor MCP en mi cliente usando modo stdio con
`uv run --directory <ruta-del-clon> python main.py --transport stdio`.
Verifica que el servidor responda antes de darlo por terminado.

Revisa siempre lo que tu asistente cambie (archivos de configuración, comandos ejecutados) antes de confirmar. Solo funciona con asistentes que pueden ejecutar comandos por su cuenta: hoy eso es Claude Code, Codex, Cursor y Windsurf en modo agente.

Claude Desktop ejecuta el paquete de PyPI con uv, sin levantar ningún servidor. Agrega esto a ~/Library/Application Support/Claude/claude_desktop_config.json (macOS) o %APPDATA%\Claude\claude_desktop_config.json (Windows) y reinicia Claude Desktop. También puedes instalar el archivo .mcpb adjunto a cada release de GitHub como extensión.

{
  "mcpServers": {
    "ecuador-datos": {
      "command": "uvx",
      "args": ["ecuador-mcp", "--transport", "stdio"]
    }
  }
}

Alternativa: conectarte a un servidor HTTP que ya corre (requiere Node.js 18+ para mcp-remote)

{
  "mcpServers": {
    "ecuador-datos": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "http://localhost:8000/mcp"]
    }
  }
}

Un comando, y listo: Claude Code lanza el servidor por stdio con uvx. Reinicia la sesión para ver los tools.

claude mcp add ecuador-datos -- uvx ecuador-mcp --transport stdio

Alternativa: servidor HTTP que ya corre

claude mcp add --transport http ecuador-datos http://localhost:8000/mcp

Abre Cursor Settings, busca "MCP" y agrega un servidor nuevo, o edita ~/.cursor/mcp.json directamente:

{

Para clientes remotos o despliegues propios. Docker exige un token (MCP_AUTH_TOKEN); el endpoint queda en http://localhost:8000/mcp. Sin Docker, uv run lo levanta en el mismo puerto.

MCP_AUTH_TOKEN="$(openssl rand -hex 32)" docker compose up -d
# o, sin Docker:
uv sync && uv run python main.py --transport http --port 8000

¿Qué es EcuDataMCP?

Un servidor MCP (Model Context Protocol) de código abierto que ayuda a tu asistente de IA a descubrir y consultar datos abiertos del gobierno de Ecuador: datasets, trámites, regulaciones, contratos públicos, riesgos, sismos, indicadores del Banco Central y compañías.

¿Qué es MCP?

Model Context Protocol es un estándar abierto para conectar asistentes de IA con herramientas y fuentes de datos externas, manteniendo el control sobre qué puede hacer el modelo y qué datos puede leer.

¿Los datos son oficiales?

Sí. Cada respuesta proviene en vivo del portal de la institución (BCE, INEC, SRI, Supercías, SERCOP…) y trae el enlace para verificarla.

¿Qué asistentes puedo usar?

Cualquier cliente compatible con MCP: Claude Desktop, Claude Code, Codex, ChatGPT (planes pagos), Cursor, VS Code, Gemini CLI, Le Chat, Windsurf, HuggingChat, y más.

¿Necesito una API key?

No. Todas las fuentes que usa el servidor son datos públicos sin autenticación. (El endpoint HTTP puede protegerse con tu propio token, MCP_AUTH_TOKEN.)

¿Es esto un servicio oficial del gobierno ecuatoriano?

No. EcuDataMCP es un proyecto independiente de código abierto que consulta las mismas fuentes públicas que ya publica el Estado ecuatoriano. No está afiliado a ninguna institución.

¿El servidor guarda mis preguntas?

No hay telemetría externa. El servidor corre localmente en tu máquina y cada consulta va directo del cliente MCP al portal oficial correspondiente. Lo único que se registra son contadores locales de uso por tool (nombre, resultado y duración, nunca los argumentos).

¿Qué formatos soporta?

Preview en memoria de CSV, TSV, JSON, GeoJSON y XLSX; consulta tabular filtrada vía el DataStore de CKAN cuando el recurso lo soporta.

Algo no funciona, ¿dónde busco?

Empieza por curl http://localhost:8000/health. Si responde, el problema suele estar en la configuración del cliente o en el portal de origen. Revisa la sección Solución de problemas más abajo.

¿Puedo contribuir?

Sí, el proyecto es MIT y acepta pull requests. Ve la guía en Cómo colaborar.

Solución de problemas

¿Algo no funciona?

Empieza por confirmar que el servidor está vivo. Si responde, el problema casi siempre está en la configuración del cliente o en el portal de origen, no en EcuDataMCP.

curl http://localhost:8000/health

Debe devolver {"status":"ok", "version": ...}. Si no responde, el servidor no está corriendo o escucha en otro puerto.

Mi cliente no muestra ningún tool

Revisa, en orden: (1) que el servidor esté corriendo (/health responde); (2) que la URL termine en /mcp, no en / ni en /health; (3) que el JSON de configuración sea válido (una coma de más lo invalida en silencio); y (4) que hayas reiniciado el cliente por completo después de editar la configuración. Claude Desktop, Cursor y Windsurf solo leen el archivo al arrancar.

Claude Desktop o Windsurf: npx no se encuentra

La alternativa con mcp-remote (y la configuración de Windsurf) necesita Node.js 18+ instalado y en el PATH. Instálalo desde nodejs.org y reinicia el cliente. Alternativa sin Node: usa modo stdio con uvx ecuador-mcp --transport stdio, o con "command": "uv" y "args": ["run", "--directory", "<ruta-del-clon>", "python", "main.py", "--transport", "stdio"].

El puerto 8000 ya está en uso

Arranca el servidor en otro puerto (uv run main.py --port 8007, o MCP_PORT=8007 docker compose up -d) y cambia la URL del cliente a http://localhost:8007/mcp.

En modo stdio el servidor se cierra al instante

Corre el mismo comando a mano en una terminal para ver el error real. Las causas típicas son una ruta incorrecta en --directory, no haber corrido uv sync en el clon, o que uv no esté en el PATH que ve el cliente (en ese caso, usa la ruta absoluta a uv).

ChatGPT o Le Chat no pueden conectarse a localhost

Los clientes web corren en la nube y no ven tu máquina. Necesitas exponer el servidor con una URL pública HTTPS (un túnel o un despliegue propio) y, en ese caso, activar MCP_REQUIRE_AUTH=1 con un MCP_AUTH_TOKEN. Nunca expongas el servidor sin token.

Error 401, 429 o 503 del servidor

401: el servidor exige token (MCP_AUTH_TOKEN) y el cliente no lo envía como Authorization: Bearer .... 429: superaste el límite de solicitudes por ventana (MCP_RATE_LIMIT_REQUESTS, 120 por 60 s por defecto); espera o súbelo en uso local. 503: demasiadas solicitudes simultáneas (MCP_MAX_CONCURRENT_REQUESTS, 8 por defecto).

Error 403 o timeout del portal de Datos Abiertos

www.datosabiertos.gob.ec a veces rechaza conexiones que vienen de fuera de Latinoamérica (error 403). Si ves esto, corre el servidor desde una conexión con salida en Ecuador o la región (por ejemplo, una VPN). Los tools de trámites e instituciones usan otro portal y no tienen este problema. Los portales del Estado también tienen caídas propias: si un solo tool falla y los demás responden, reintenta más tarde.

Error de certificado TLS / SSL

Algunos portales oficiales han publicado certificados vencidos o con la cadena incompleta (el de Datos Abiertos venció en julio de 2026). Para ese portal existe un reintento opt-in: CKAN_INSECURE_TLS=1 en tu .env. Úsalo solo mientras dure la falla del portal y quítalo después.

El preview sale cortado o dice que el archivo es muy grande

Es intencional: las descargas se limitan a 5 MB y la descompresión de ZIP/tar.gz a 20 MB. Para recursos grandes usa query_resource_data (filtra en el DataStore de CKAN sin bajar el archivo) o list_zip_contents para ver qué trae un ZIP y read_zip_member para leer uno de sus archivos sin bajar el ZIP entero.

Necesito más detalle para reportar un bug

Arranca con LOG_LEVEL=DEBUG, reproduce el error y abre un issue en GitHub con el tool, los parámetros, la salida de /health y el log. No incluyas tokens.
